# Fixture corpus

Test fixtures copied verbatim from Miniflux **v2.3.3** at commit `c4d54f87`. Miniflux is
licensed under the Apache License, Version 2.0; the license text is in `/LICENSE` and the
attribution in `/NOTICE`.

Nothing here is generated by Rivulet: every file is a byte-for-byte copy of the upstream
file of the same name, so any behavioral difference in the tests is a difference in the
implementation under test, never in the input. Directories mirror the upstream
`internal/reader/<area>/testdata` layout:

| Directory | Upstream path | Files |
| --- | --- | --- |
| `encoding/` | `internal/reader/encoding/testdata` | 11 |
| `parser/` | `internal/reader/parser/testdata` | 8 |
| `parser/golden/` | not an upstream file — the reference's output, see below | 8 |
| `xml/` | `internal/reader/xml/testdata` | 3 |
| `sanitizer/` | `internal/reader/sanitizer/testdata` | 2 |
| `sanitizer/hostile_corpus.txt` | not an upstream file — the corpus the plan names, see below | 1 |

Upstream tests for these files live next to them (`encoding_test.go`, `decoder_test.go`);
where a Rivulet test mirrors an upstream assertion, it names the upstream test in a comment.
The whole corpus is copied in one go so that later slices of stage 3 work on the same inputs;
the parser fixtures are used upstream only as benchmark and fuzz inputs — no upstream test
asserts their parsed output, so the parser tests define their own expected values as golden
files. As of the charset, the XML reader, the parser corpus and the hostile sanitizer corpus
slices, `encoding/`, `xml/`, `parser/` and `sanitizer/` are read by tests.

`parser/golden/` and `sanitizer/hostile_corpus.txt` are the two things here that are not copies of
an upstream file. The golden files are the reference's output on the fixtures above — each file says
so on its own line — and the corpus is the reference's output on inputs of our own, written by
running Miniflux v2.3.3 (Go 1.26, the version `miniflux/go.mod` pins) with the clock fixed to UTC.
Neither is Rivulet's output: both record what the reference produces, so a test failing against them
is a difference in the implementation under test. Each names the rule its input pins and what that
input cannot pin; regenerating either means running the reference again, never running Rivulet.

To refresh the corpus, copy the files again from the pinned commit rather than editing
them here; a local edit would silently invalidate the provenance above.
