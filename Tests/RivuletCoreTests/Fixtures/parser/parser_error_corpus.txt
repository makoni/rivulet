# The parser error corpus: the inputs the typed error and the switch decide on, read through
# the reference's own path.

# Every value is the reference's own output for the input above it, produced by running
# Miniflux v2.3.3 at commit c4d54f87 (Go 1.26.0) through DetectFeedFormat and the switch
# ParseFeed makes, with TZ=UTC. The method is recorded in docs/testing.md. A control byte is
# written as an escape form, and the decision, the outcome and the end state are the
# reference's output for the case above it, so they are not wrapped here: breaking them
# would change what they say.

# Each rule line names the rule of the case under it, and every case here can fail on that
# rule: a case is left out when a wrong implementation of the rule it names writes the same
# values. So this corpus does not pin the size of the buffer the JSON rule reads, or that
# the rule reads until the first character rather than to the end, because a wrong
# implementation of those writes the same decision, nor the number the cap counts, since a
# root read as the 50th token and one read as the 51st give the same answer. It pins only
# that the scan stops before the switch when the count reaches the cap. It also cannot pin
# the wording of a failure: it pins the case the message names, which the test that reads
# this file spells out, and the outcome line names the branch the switch takes, which for a
# routed case is the reference's answer that no failure was reported.

# Two things the comparison treats as equal are recorded in docs/parity.md: the reference
# reports io.EOF at a clean end of the document, where the port reports its unexpectedEOF
# case, and the port keeps one case for a failure, so its message is not part of what a pin
# can compare.
# a JSON document is decided before any XML token is read, so a feed element inside it does
# not decide the format
input = \n\t{\n\t\t\"version\": \"https://jsonfeed.org/version/1\",\n\t\t\"title\": \"Example\",\n\t\t\"feed\": \"x\"\n\t}\n
decision = json
outcome = routed to the json adapter
end = EOF

# the character that decides the JSON rule is the first one that is not whitespace, so mixed
# whitespace before the root is read through the buffer
input = \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  \n\t  {\"version\":\"1\"}
decision = json
outcome = routed to the json adapter
end = EOF

# a document that ends without a character is not decided by the JSON rule, because the rule

# the scan reaches the cap and stops before the switch on the name, so a root read as the
# 50th token is not the answer
input = <p><i>0</i><i>1</i><i>2</i><i>3</i><i>4</i><i>5</i><i>6</i><i>7</i><i>8</i><i>9</i><i>10</i><i>11</i><i>12</i><i>13</i><i>14</i><i>15</i><i>16</i><i>17</i><i>18</i><i>19</i><i>20</i><i>21</i><i>22</i><i>23</i><i>24</i><i>25</i><i>26</i><i>27</i><i>28</i><i>29</i><i>30</i><i>31</i><i>32</i><i>33</i><i>34</i><i>35</i><i>36</i><i>37</i><i>38</i><i>39</i><i>40</i><i>41</i><i>42</i><i>43</i><i>44</i><i>45</i><i>46</i><i>47</i><rss></rss>
decision = unknown
outcome = parser: unable to detect feed format
end = XML syntax error on line 1: unexpected EOF

# the attribute the reference reads is the one whose name is version, whatever prefix it is
# written with, so a prefixed version attribute decides the version like an unprefixed one
input = <feed xmlns:a=\"http://purl.org/atom/ns#\" a:version=\"0.3\">
decision = atom 0.3
outcome = routed to the atom adapter
end = XML syntax error on line 1: unexpected EOF

# a scan that fails before a root is read ends it without an answer, and the failure is the
# case for an angle bracket inside an attribute value
input = <rss attr=\"<\">x</rss>
decision = unknown
outcome = parser: unable to detect feed format
end = XML syntax error on line 1: unescaped < inside quoted string

# the scan ends with the answer unknown for a document with no feed root, which is the case
# the typed error is reported for
input = \n\t<!DOCTYPE html> <html> </html>\n\t
decision = unknown
outcome = parser: unable to detect feed format
end = EOF

# a document that is text only has no root to decide on, so the typed error is reported for
# it
input = garbage
decision = unknown
outcome = parser: unable to detect feed format
end = EOF
